Python学习笔记：从“田字格绘制”看函数与代码复用的艺术

2026-10-23
字数统计: 1.2k   |   阅读时长≈ 4 分钟

前言：最近在学Python的“函数与代码复用”这一章。老实说，刚开始觉得定义函数有点多此一举，明明几行 print 能搞定的事情，非要包个 def。直到遇到了这道经典练习题——“字符田字格绘制”，我才真正体会到：如果不写函数，这种图形题能把手敲断。

一、 题目需求分析：为什么需要函数？

题目要求：用字符打印一个田字格，要求采用函数方式，以宽度为参数，绘制任意大小的图形。

二、 逻辑拆解与函数封装

  • 竖线：由竖线和空格组成。

四、 深度复盘：代码复用体现在哪里？

  1. 逻辑复用的极致：主程序里那个内层循环 for _ in range(4): draw_line2(size)。如果没有函数，你必须在循环里写4次长长的 print 语句。而现在，你只需要调用4次 draw_line2，代码瞬间从“裹脚布”变成了“短小精悍”的诗。

  2. 参数化的灵活性：因为我们把宽度交给了参数 n，所以这个函数一次编写，处处运行。输入3就是迷你版，输入10就是超大号。这就是函数复用带来的高扩展性。

  3. Pythonic语法在函数内的复用：在 draw_line1 和 draw_line2 内部，我没有写笨重的 for 循环去拼接字符，而是直接用 字符串 * 整数 语法。这不仅是对底层字符的复用，更是对 Python 高效特性的复用。

五、 踩坑与反思

  1. 对齐问题：一开始我在 draw_line1 里写的是 '+----+'，在 draw_line2 里写的是 '| |'。虽然逻辑没错，但因为终端字体高度通常大于宽度，画出来的格子全是扁的。后来加上空格（'+ - - - - '），并让竖线后的空格数与之匹配（9个空格），才实现了视觉上的完美正方形。

  2. 边界处理：嵌套循环结束后，千万别忘了在代码最后再调用一次 draw_line1(size) 封底。这是一个典型的代码逻辑边界问题，也是很多初学者容易犯的错误（图形漏风）。

总结

这道题表面上是练习画图，本质上是培养我们“提取公共逻辑，减少冗余代码”的工程思维。一旦学会了封装函数，以后不管遇到画什么图形、处理什么复杂数据，我们都能从容应对。
