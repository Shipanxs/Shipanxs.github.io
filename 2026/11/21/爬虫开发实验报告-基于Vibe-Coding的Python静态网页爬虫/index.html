爬虫开发实验：基于 Vibe Coding 的 Python 静态网页爬虫

桂林理工大学「桂工要闻」列表页抓取实验报告

一、实验目的

  1. 掌握 Vibe Coding 的核心工作流（意图定义、任务拆解、验证闭环），改变传统逐行编写代码的习惯。
  2. 学会使用结构化 Prompt 驱动 AI 生成 Python 爬虫代码（基于 requests 与 BeautifulSoup）。
  3. 掌握对 AI 生成代码的审查、调试与重构能力，建立反爬合规意识。

二、实验环境

  1. 操作系统：Windows（本次实验在本地电脑上完成）。
  2. Python 3.9 及以上版本（本次实际运行环境为 Python 3.13）。
  3. AI 编程助手。
  4. 核心依赖库：requests、beautifulsoup4、pandas。本次实验实际仅使用 requests、beautifulsoup4 以及 Python 标准库 csv 完成 CSV 写出，pandas 未涉及。

三、实验任务与场景

（一）场景背景

抓取桂林理工大学「桂工要闻」列表页（https://glut.edu.cn/ggyw/424.htm），提取每篇文章的标题、发布时间、作者、链接四个字段，并保存为结构化的 result.csv 文件。

（二）Vibe Coding 核心约束

  1. 禁止直接让 AI 一次性生成所有代码。
  2. 必须采用“需求澄清 → 分步生成 → 运行验证 → 报错反馈”的迭代流程。

四、实验步骤

步骤 1：需求澄清与结构化 Prompt 编写

按照“角色 + 目标 + 约束 + 验收标准”的格式编写结构化需求，而不是笼统地说“帮我写个爬虫”。本次实验使用的结构化 Prompt 如下：

结构化 Prompt

你是 Python 后端工程师。我需要编写一个静态网页爬虫。目标：抓取桂林理工大学「桂工要闻」列表页 https://glut.edu.cn/ggyw/424.htm ，提取每篇文章的标题、发布时间、作者、链接。约束：使用 requests 和 BeautifulSoup；必须设置真实浏览器 User-Agent 伪装；请求间隔不低于 2 秒；遇到网络超时需重试 3 次。验收：输出 result.csv 文件，并在终端打印成功抓取条数。

在此基础上，进一步通过提问确认了以下需求细节：

  1. 列表结构：ul.list_box_riqi > li > a[href]；时间位于 div.time 内，由 h3（日）和 h6（年-月）组成。
  2. 作者字段：列表页不直接展示作者，统一填空字符串。
  3. 分页：本次仅抓取 424.htm 单页。
  4. 时间格式：将 h6 与 h3 的内容拼接为 YYYY-MM-DD 格式。
  5. 链接：页面内为相对路径，需补全为以 https://glut.edu.cn/ 开头的完整 URL。
  6. 输出：result.csv 放在项目根目录，编码使用 utf-8-sig，列名固定为 title、publish_time、author、url。
  7. 合规：robots.txt 经访问返回 404，视为允许抓取；仅抓取公开新闻列表数据并控制请求频率。

步骤 4：代码审查与工程化重构

将上述全部代码喂回 AI，进行代码审查，并重构为面向对象的 NewsCrawler 类，保持功能不变。

（1）代码审查意见（摘要）

  1. 性能方面：apparent_encoding 每次请求都做字符集探测，结果不稳定，建议显式指定编码；单页数据量小，无明显性能瓶颈。
  2. 异常处理：time_div 下的 h6/h3 若不存在会抛 AttributeError；fetch 未区分超时与 4xx/5xx，确定性失败也会被重复重试。
  3. 反爬合规：代码内无 robots.txt 检查（本次已人工确认 404 允许）；固定单一 User-Agent，长期高频抓取易被识别。
  4. 安全方面：相对路径覆盖写可能误覆盖已有 result.csv；标题若以 =、+、-、@ 开头存在 CSV 公式注入风险（本场景风险较低）。

（2）重构后的 NewsCrawler 类

重构后保持 requests + BeautifulSoup、User-Agent 伪装、超时重试 3 次、utf-8-sig 编码、字段名与文件名完全不变，同时补充了 h6/h3 的 None 防护。

五、实验总结

本次实验完整走通了 Vibe Coding 的“需求澄清 → 分步生成 → 运行验证 → 报错反馈”流程，主要收获如下：

  1. 学会了用“角色 + 目标 + 约束 + 验收标准”的结构化 Prompt 精确描述需求，避免了 AI 一次性生成不可控代码。
  2. 体会到分步生成与最小化验证的价值：每一步先验证再推进，能够快速定位问题（如标题为空的 HTML 结构问题）。
  3. 掌握了 requests + BeautifulSoup 静态网页抓取的基本方法，以及 CSV 持久化、utf-8-sig 编码处理和异常容错。
  4. 建立了代码审查意识，能从性能、异常处理、反爬合规、安全四个维度审视 AI 生成的代码，并通过重构提升可读性与可维护性。

存在的问题与不足：本次仅完成单页抓取，尚未涉及分页遍历、动态渲染页面与更复杂的反爬处理，后续可在进阶挑战中继续实践。
