python实验-蒙特卡罗方法手搓图形

2026-11-22
字数统计: 1.4k   |   阅读时长≈ 5 分钟

这次的实验题目是”用蒙特卡罗方法估算 π，并把过程画出来”。一开始以为要写一大堆循环和判断，真动手才发现核心逻辑只有四五行，剩下的时间基本都花在调图上——中文乱码、圆被压成椭圆、图例把散点挡住，一个比一个磨人。

一、思路：把 π 藏进一个面积比里

在 0 到 1 的正方形里随便撒点，再画一个以原点为圆心、半径为 1 的四分之一圆，那么：

  • 正方形的面积是 1；
  • 四分之一圆的面积是 π / 4；
  • 点撒得够多、够均匀时，”落在圆内的点数 / 总点数”就近似等于”圆面积 / 正方形面积”，也就是 π / 4。

反过来推一下，π ≈ 4 × 内点数 / 总点数。整个算法就这一句话。

二、代码实现

几个值得记下来的写法：

  1. 不要用 for 循环。 np.random.rand(n) 一次性生成 n 个 [0,1) 的随机数，numpy 的向量化运算比 Python 循环快一两个数量级，撒 100 万个点也就零点几秒。
  2. inside = x**2 + y**2 <= 1 是布尔数组。 拿它当下标 x[inside] 就能直接取出所有圆内的点，不需要另建列表。
  3. 判据用 <= 1。 落在圆周上算”内”还是”外”其实无所谓，边界上的点概率为 0，对结果没有影响。
  4. 统计用 inside.sum()。 布尔数组求和会把 True 当 1、False 当 0，直接就是内点个数。

三、跑出来的结果

这次取 n = 10000，落在圆内的点有 7837 个，估算值：

π ≈ 4 × 7837 / 10000 = 3.1348

和真值 3.14159 差了 0.0068。图上蓝色点密密麻麻挤满左下角的扇形，红色点全部堆在右上角那一块——视觉上一眼就能看出”面积比 ≈ 概率比”这件事。

四、画图踩过的坑

代码逻辑五分钟就写完了，图却改了半小时，问题都出在细节上：

  • 中文变方块、负号消失。 必须提前设 font.sans-serif = ['Microsoft YaHei']（Windows 上 SimHei 也行），再设 axes.unicode_minus = False，否则标题里的中文和负号都会出问题。
  • 圆被压成椭圆。 matplotlib 默认按画布比例拉伸坐标轴，一定要加 set_aspect('equal')，否则半径 1 的圆看着像个扁馒头。
  • 图例压住散点。 一开始图例放在图里，正好盖住右上角的红点。改成 bbox_to_anchor=(1.05, 1), loc='upper left'，图例就挪到了图外右侧；figsize 从 (5, 5) 调成 (6, 5)，给它留出位置。
  • 图例的点太小。 散点本身 s=1，图例里的示例点也跟着变成一个小像素，根本看不清。markerscale=8 把它单独放大八倍。
  • 图例被裁掉一半。 图例移到图外后，保存时右半边会丢，加一句 plt.tight_layout() 让布局自动收缩。
  • 点糊成一片。 点一多，s=1 也会互相重叠，这是密度高的必然结果，反而正好体现了”越密越接近理论面积”。

五、误差分析

蒙特卡罗的误差是统计性的，不是代码写错了。n 个点时的估计标准差大致是

σ ≈ 4 × √(p(1-p)/n)，其中 p = π/4 ≈ 0.785

代入 n = 10000，σ ≈ 0.016，相对误差约 0.5%。这次的偏差 0.0068 还不到半个 σ，属于非常正常的一次抽样。这也解释了为什么它收敛得”慢”：误差按 1/√n 下降，想让误差减半就得撒四倍的点，想多要一位小数的精度，n 得涨一百倍。

顺手写了个对比脚本，看看 n 变大时误差怎么走：

大致会看到误差从 0.05 量级一路降到 0.005 左右，每加一个数量级的点，误差差不多缩小到三分之一。

六、小结

蒙特卡罗方法最迷人的地方在于它”绕过”了推导：不用积分公式，不用级数展开，只要会生成随机数、会数点，就能算出 π。代价是精度提升极慢，1/√n 这条曲线注定了它不适合要求高精度的场合，但在高维积分、复杂边界这类传统方法算不动的问题上，它反而是最省事的选择。

这次实验最大的收获其实不在算法，而在画图：一份实验结果，数据对不对是一回事，别人能不能一眼看懂是另一回事。set_aspect、bbox_to_anchor、tight_layout 这几个参数，以后大概每次画图都要用到。
